# 真实仪表安全清单

在把任何新驱动、新模块或新接线接到昂贵样品、超导磁体或低温系统之前，请逐项核对这份清单。**只要有一项拿不准，就停留在只读或仿真模式，不要直接进入自动运行。**

## 1. 上电与接线前（硬件层）

- [ ] 核对实体仪表的完整型号、选件板卡、固件版本和通讯接口（GPIB / USB / 串口 / 网口）。
- [ ] 在**仪表本机面板**设好限流、限压、限温、磁体保护和物理联锁。
- [ ] 确认人工急停按钮的位置，并清楚断电后各仪表的默认动作。
- [ ] 首次测试使用假负载（如标准电阻）或能承受最坏输出的非关键样品。
- [ ] 检查软件配置中的地址与上下限，确保不会误连到旁边的另一台设备。

## 2. 连接与初始化（`open`）

- [ ] 导入代码和构造对象阶段不发生任何硬件通信。
- [ ] 所有通讯会话都设置了有限 I/O 超时。
- [ ] 连接后的第一条命令是查询身份/状态（只读），而不是下发修改命令。
- [ ] 型号或固件不匹配时立即报错退出，不继续操作。
- [ ] 启用或加载历史设置只填界面，绝不自动下发到仪表。
- [ ] 初始化进行到一半失败时，已打开的句柄能干净关闭。

## 3. 写入与参数设置

- [ ] 核心配置、驱动代码和仪表本机三层都设置了安全边界。
- [ ] 后端发命令前重新校验单位、有限数值、正负号和量程。
- [ ] 写入关键参数后读回确认，不一致则报错停止。
- [ ] 写命令超时视为“结果不确定”，绝不盲目重发。
- [ ] 多步配置中途出错时，能明确识别仪表处于部分配置状态。

## 4. 测量过程（Measurement Module）

- [ ] 通道切换、等待、触发与读数顺序与仪表手册一致。
- [ ] 单次 I/O 超时远小于框架总操作超时，为异常关断输出留足余量。
- [ ] 已用测试覆盖：正常读数、超量程、compliance、乱码响应及对应数字状态码。
- [ ] 单点数据无效时留空测量列、写非零状态码并报 Warning；通信中断或输出状态不明时直接抛 Error 停机。
- [ ] 若输出 `rawdata`，确保全为有限数字且行数与主 DAT 严格对齐。

## 5. 暂停、停止与异常收尾

- [ ] 长循环与多次 I/O 之间调用 `api.checkpoint()` / `api.sleep()` 响应 Pause/Stop。
- [ ] 人工确认点击 **Pause** 不会引起意外输出跳变。
- [ ] 正常完成、Stop、Error 三种 `run_end` 都能按约定关闭输出（若提供跨 SEQ 保持偏置选项，必须默认关闭，保持前回读确认，且 Disable / 重新 Apply / 异常时仍强制关闭）。
- [ ] 确认 SEQ 完成、Stop 或 Error 不会擅自给系统仪表发 Set 或 Hold。
- [ ] `close()` 可重复调用，即使某台仪表关闭出错，其余会话也会继续释放。

## 6. 系统仪表特别检查（System Instrument）

- [ ] `read_status()` 返回有限数值与真实状态。
- [ ] `hold()` 使用同一次操作里现读的新鲜值，绝不用旧缓存或 0。
- [ ] 断线重连后先读回真实目标和速率，绝不重放旧写命令；恢复超时后进入 Faulted 并禁止写入。
- [ ] 确认 `sample_temp` / `field` 角色配置唯一且正确。

## 7. 分阶段实机放行

- [ ] **阶段 1（只读）**：只核对地址、型号、读数和状态位。
- [ ] **阶段 2（假负载低风险写入）**：用最小安全输出试跑单步命令并核对仪表面板。
- [ ] **阶段 3（故障演练）**：人为拔线、制造超时、点击 Stop 和触发 Error，观察收尾是否符合预期。
- [ ] **阶段 4（归档）**：保存脱敏后的命令日志与测试结论；全部确认前保持 Beta 标记，不无人值守运行。

!!! danger "进程结束 ≠ 外部仪表已安全"

    软件强杀后台子进程只能回收电脑本地资源，无法保证外部仪器已经关掉输出或停止升场。
    最终安全永远依赖仪表本机保护、硬件联锁与人工急停。
