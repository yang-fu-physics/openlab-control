# 怎样检查和测试测量模块

测试分两步走：**先在电脑上用假连接验证全部逻辑和异常路径**，把代码里的坑全清干净，**再接假负载做低风险真机验证**。

## 1. 先跑一遍自带的教学模块测试

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -p "test_bundled_*.py" -v
```

可以参考 `tests/test_bundled_tutorial_resistance.py` 的写法，为自己的模块编写同类测试。

## 2. 离线自动化测试应覆盖的场景

**模块生命周期与数据契约**

- 正常的 Enable → Apply Settings → Measure → Disable 流程；
- 未点击 Apply Settings 直接测量时明确拒绝；
- 连接或配置进行到一半报错时，已打开的句柄仍能干净关闭；
- 仪表 `*IDN?` 型号不匹配时立即拒绝，不发送后续配置命令；
- 多通道模块每行只填本通道列，未测列和异常点测量值留空；
- 正常、超量程、compliance、乱码响应分别映射到正确的整数 `StatusCode`；
- 在等待步骤中测试 `Pause` 和 `Stop`；
- 正常完成、Stop、Error 三种 `run_end` 均按约定收尾输出；
- 重复调用 `close()` 不报错，且一台仪表关闭失败不影响其余仪表释放。

**底层仪表协议（用假连接检查）**

- 不仅验证最后算出的数值，更要断言**发送给仪表的完整命令顺序**；
- 覆盖空回包、乱码、`NaN` / `Infinity` 与超量程哨兵值；
- 写命令超时时不自动重发；
- 每次 I/O 都配置了有限超时。

**前端界面（如果写了 `frontend.py`）**

- `load()` 后再 `dump()` 数值保持一致；
- `load()` 和加载 SEQ 绝不触发连接或 Apply；
- 初始窗口宽度合适，不出现横向滚动条。

如果同时改动了核心源码，提交前还需运行全量核心测试：

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

## 3. 低风险真机检查步骤

1. **先不接样品**：只做只读连接，核对型号、固件和当前状态；
2. **接假负载**：在仪表本机设好最低风险的限流/限压/量程；
3. **单步核对**：每下发一次配置，立即回读并与仪表面板对照；
4. **故障演练**：人为测试 Stop、拔线、超时，确认输出按预期安全收尾；
5. **留档放行**：确认硬件联锁与急停可靠，保存脱敏命令日志。未完成真机验证前请标明 Beta，勿无人值守运行。
